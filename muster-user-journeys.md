# Muster — User Journeys

1. **First sign-up.** A new user signs up, names their organisation, picks Holly as their first teammate, is offered a Remote.com or CSV connection and skips it for now, and lands on Home. The team strip shows Holly active. The goal box is empty and inviting, not blank and confusing.

2. **Running a payroll cycle.** On Home, the user types "Run September payroll" into the goal box. It becomes a thread: Holly acknowledges, then reports back in plain language as Input, Structure, and Tax each finish — "Checked attendance for 40 people, 2 things need your review." A message in the thread links straight to those 2 items on Catchup. The user does not have to know these are three separate agents to follow what happened.

3. **Clearing Catchup.** The next morning, the user opens Catchup and sees "2 things need you." Each card is self-explanatory without clicking anything else — who it's about, what was found, why Holly's unsure, in plain language. The user approves one and corrects the other with a one-line note. Both disappear from "Needs you now" and reappear in "Recently resolved." Nothing the user typed required knowing a database field name.

4. **Teaching Holly a rule.** The user opens Holly's page, the Rules tab, and pastes a PT slab table from their own calculation sheet. Holly extracts what's literally stated and proposes it. It shows up on Catchup as a normal item — same card shape as any other approval. The user approves it. The next payroll cycle uses it automatically; the user never has to know it's called a "confirmed rule" internally.

5. **Connecting a data source.** The user opens Marketplace, finds Remote.com under People & attendance data, clicks Connect, and pastes in their sandbox token. The card now reads "Connected." Back on Holly's Data sources tab, the same connection shows there too — one underlying state, shown in two places consistently.

6. **Adding a second teammate** (once one exists). The user opens Team Members, sees a second card no longer marked "coming soon," and activates it the same way Holly was activated during onboarding — without being sent back through the onboarding flow itself.
